# 课程视频质量检查清单

每次截帧/编码前必须逐项检查。任何一项不通过 = 不交付。

---

## 铁律（违反=工程崩溃）

### 铁律1：sub-agent报告必须验证，不能信
- sub-agent声称"全部通过"≠真的通过
- 它会编造看起来很完整的假数据（行号、字数、时间戳全捏造）
- **任何sub-agent产出的检查报告，必须自己抽查至少2项原始数据**
- 方法：直接grep/read_file原文件，对比报告中声称的内容

### 铁律2：字幕数据必须从VTT文件解析，不能手写
- 禁止凭记忆或感觉写时间戳
- 禁止把一整段话塞进一条subtitle（每条<=20字）
- 流程：parse VTT → split long entries → 写入HTML
- 写入后必须逐条对比VTT原文验证

### 铁律3：截帧后必须视觉自查
- 截帧完成后抽查3-5帧（首帧、中帧、末帧）
- 检查：有内容、字幕可见、不溢出、场景正确
- 文件大小<100KB的帧=空白帧，必须排查

---

## 1. 画面渲染

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 1.1 | 每帧画面可见 | 无空白/纯黑帧，文件>100KB | `ls -la frames-lXX/ \| awk '$5<100000'` |
| 1.2 | seekTo瞬间切换 | 截帧间隔80ms内必须完成场景切换，禁止异步动画 | Playwright截图后检查scene active状态 |
| 1.3 | GSAP动画兼容 | seekTo用`gsap.set()`不用`gsap.to()`，避免动画未完成就被截帧 | 代码审查：showScene函数 |
| 1.4 | CSS transition兼容 | `.scene`如有`transition:opacity`，seekTo时必须设inline opacity覆盖 | grep `transition.*opacity` |
| 1.5 | 竖屏适配 | 所有元素在1080x1920内完整显示，无溢出 | 视觉自查3-5帧 |

## 2. 字幕格式

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 2.1 | 竖屏限宽 | `left:60px;right:60px`或`max-width:960px`，禁止`white-space:nowrap` | CSS审查 |
| 2.2 | 单条字幕长度 | 15-20字/条，绝不超过20字 | 字幕数据审查，`awk 'length>N'` |
| 2.3 | 不铺满屏幕 | 字幕占屏幕面积<15%，不能堆成一段话 | 视觉自查 |
| 2.4 | 允许换行 | 长句自动折行，不横向溢出 | 视觉自查 |

## 3. 字幕时间线

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 3.1 | 时间戳来源 | 必须用VTT文件的精确时间戳，禁止手估 | 对比voiceover.vtt |
| 3.2 | 语音同步 | 字幕出现/消失与语音完全对齐 | 播放视频逐句检查 |
| 3.3 | 无时间间隙 | 相邻字幕end==下一条start，无空白间隙 | 脚本检查时间连续性 |
| 3.4 | 无时间重叠 | 相邻字幕不能重叠 | 脚本检查 |
| 3.5 | 覆盖完整 | 字幕时间范围=VTT时间范围 | 对比总时长 |

## 3.5 VTT 内容验证（必须在截帧前做）

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 3.6 | VTT内容 vs script.txt | VTT 讲的内容必须和 script.txt 一致（不是只看标题，逐条对比关键术语） | 人工读前3条 VTT 和 script.txt 首段 |
| 3.7 | VTT时间戳无重叠 | 上一条 end <= 下一条 start | 脚本检查 |
| 3.8 | VTT总时长 vs MP3时长 | 误差 < 1s | ffprobe 对比 |

**如果 VTT 内容和 script.txt 不匹配**：用 faster-whisper 转录 MP3 验证实际语音内容，然后用 script.txt 原文 + whisper 时间戳重写 VTT。详见 `references/capture-and-subtitle-pitfalls.md` 第7条。

---

## 4. 编码输出

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 4.1 | 分辨率 | 1080x1920竖屏 | `ffprobe` |
| 4.2 | 帧率 | 15fps（Mode3 用 30fps） | `ffprobe` |
| 4.3 | 编码器 | h264_nvenc -preset p5 -cq 20 | FFmpeg命令审查 |
| 4.4 | 像素格式 | yuv420p | FFmpeg命令审查 |
| 4.5 | 时长正确 | 与VTT总时长一致，误差<0.5s | `ffprobe` |

---

## 5. 审美审核（主观但必须过）

| # | 检查项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 5.1 | 动画居中不占满 | 核心动画元素在屏幕中心区域（上下左右各留≥10%呼吸空间），不能贴边或铺满全屏 | 截帧视觉自查 |
| 5.2 | 动效自然流畅 | 缓动曲线合理（ease-out为主），无突兀跳变、机械感、鬼畜循环 | 逐场景播放观察 |
| 5.3 | 元素层次分明 | 前景（文字/卡片）与背景（光球/粒子）有清晰的主次关系，不能混成一团 | 截帧视觉自查 |
| 5.4 | 留白充足 | 文字与文字、文字与边缘之间有足够间距，不拥挤不压迫 | 截帧视觉自查 |
| 5.5 | 色彩和谐 | 主色/辅色/强调色搭配协调，霓虹可以亮但不能刺眼杂乱 | 整体画面审视 |
| 5.6 | 整体画面美观自然 | 退后一步看：像不像一个专业课程视频？有没有"AI味"（过度对称、元素堆砌、动画过满）？ | **最关键**：截图发给User审核前自己先看3秒，觉得不舒服就调 |

**审核原则**：工程正确≠好看。5.1-5.6任何一项不过，回去调，不要抱着"技术没问题就交付"的心态。

---

## 检查流程（截帧前）

```
□ 1. 打开HTML，检查seekTo是否能正确切换场景
□ 2. 检查字幕CSS：限宽、允许换行、无nowrap
□ 3. 检查字幕数据：每条<=20字，时间戳与VTT一致
□ 4. 检查sceneBounds：与VTT时间戳一致
□ 5. 截帧后：抽查5帧，确认有内容
□ 6. 审美审核：动画居中、动效自然、层次分明、留白充足、色彩和谐
□ 7. 编码后：ffprobe检查分辨率/帧率/时长
□ 8. 播放检查：字幕同步、画面连续、音频正常
□ 9. 最终审核：截图看3秒，觉得不舒服就调，不要交出去
```
